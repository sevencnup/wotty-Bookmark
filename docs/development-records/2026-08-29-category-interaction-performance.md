# 分类管理交互卡顿优化

## 目标

定位并修复分类管理页面在大量书签下展开、收起和打开书签操作延迟约一秒的问题。

## 执行步骤

1. 建立大量书签场景下的计算和浏览器交互耗时基线。
2. 区分分组计算、React 重渲染、CSS 动效和浏览器新标签页行为。
3. 针对确认的主线程阻塞点减少无关书签行渲染。
4. 增加性能回归验证，确保展开/收起不会重建未变化分组。
5. 更新开发记录与版本记录，执行测试、构建并完成本地提交。

## 验收标准

- 单个文件夹展开/收起获得即时视觉反馈。
- 点击书签链接不会被页面同步计算和无关列表渲染阻塞。
- 现有搜索、整组选择、拖拽和批量移动功能保持可用。
- 临时测试脚本和调试进程全部清理。

## 诊断结论

- 真实数据包含 1017 条书签、249 个可见分组和 274 个组织树节点。
- 优化前单个分组收起/展开需要 688～1316ms，可稳定复现用户反馈的一秒延迟。
- 原生书签链接点击事件仅需约 1ms，卡顿来自 React 重渲染，而非接口、CSS 动画或链接事件。
- 每次切换一个分组时，页面会重新计算分组并重建全部书签行，同时让右侧组织树参与 React 协调。

## 实施结果

- 缓存书签过滤、文件夹扁平化和书签分组计算。
- 将书签分组拆为独立记忆化组件，单个分组切换时不再重渲染其他分组。
- 隔离缓存右侧组织树，左侧分组状态变化不再触发 274 个树节点重新协调。
- 为分组内容增加浏览器布局与绘制隔离，屏幕外分组延迟渲染。

## 性能结果

- 单个分组收起/展开：由 688～1316ms 降至 19～53ms，提升约 20～35 倍。
- 收起全部：约 190ms。
- 展开全部：约 771ms；该操作需要一次创建全部 1017 行，属于批量操作。
- 书签链接事件：约 0.8ms。

- `pnpm --filter @bookmark-vault/admin-web build`：通过。
- 临时浏览器、测试会话、数据库副本、脚本和独立 API 进程已清理。
