# 分类管理文件夹高度一致性修复

## 目标

修复分类管理左侧书签分组在滚动和收起状态下出现顶部空白、文件夹高度视觉不一致的问题。

## 执行步骤

1. 对比分组容器与分组标题的滚动后布局位置。
2. 排查 sticky 定位、固有尺寸估算和多层样式覆盖。
3. 修正分组标题定位并保留列表表头吸附行为。
4. 验证展开、收起、滚动和窄屏布局。
5. 更新开发与版本记录，执行测试、构建并完成本地提交。

## 诊断结论

- 分组标题使用了 `position: sticky` 和 `top: 43px`。
- 滚动时标题被吸附到列表顶部，但所属 `section` 仍保留原始位置，因此父容器高亮区域与标题视觉位置分离，形成半格空白。
- 文件夹数据、标题长度和收起状态本身没有改变行高。

## 实施结果

- 分组标题恢复普通文档流定位，不再参与 sticky 吸附。
- 列表列标题继续使用 sticky，滚动时仍保持在列表顶部。
- 增加最终优先级覆盖，避免旧缓存样式重新启用分组 sticky。

## 验证结果

- Chromium 使用真实 1017 条书签，全部收起后滚动 2400px。
- 连续检查 10 个收起分组，容器顶边与标题顶边差值均为 0px。
- 10 个分组总高度全部为 53px，标题 52px 加 1px 分隔线。
- `pnpm --filter @bookmark-vault/admin-web lint`：通过。
- `pnpm --filter @bookmark-vault/admin-web test`：17 项通过。
- `pnpm --filter @bookmark-vault/admin-web build`：通过。
- 临时会话、浏览器和测试脚本已清理。

## 验收标准

- 每个收起文件夹仅占一个统一高度的标题行。
- 分组容器顶边与标题顶边一致，不再产生额外空白占位。
- 列表表头、分组操作和性能优化保持正常。
