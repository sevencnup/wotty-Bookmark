# 后台运行时错误排查

## 目标

定位后台管理页面出现 API 500、Vite 连接拒绝，以及浏览器扩展 `getComputedStyle` 异常的根因，并修复可归属本项目的问题。

## 执行步骤

1. 检查 56993 前端、26626 API 和侧边栏扩展相关进程及端口状态。
2. 直接启动 API，采集启动日志并复现存储、应用密码和书签接口。
3. 启动前端并确认 Vite 服务稳定运行，区分服务退出与代理故障。
4. 检查侧边栏脚本 `getComputedStyle` 来源，区分仓库代码与浏览器扩展注入脚本。
5. 更新开发记录与版本记录，执行相关测试/构建并完成本地提交。

## 验收标准

- API 启动稳定，相关接口返回预期状态。
- 前端 56993 可持续访问，API 断开时保留页面并显示清晰的连接错误。
- 明确 `sidebar.js` 是否属于仓库代码。
- 临时进程在验证结束后全部关闭。

## 排查结论

- API 直接启动后 `/health/live` 返回 200；存储状态、应用密码和书签接口未登录时返回预期 401。
- 使用隔离账号及真实账号数据副本验证，三个接口均返回 200，未能复现数据库查询必然失败。
- 控制台中的 Vite WebSocket 断开和后续 `ERR_CONNECTION_REFUSED` 源于开发服务退出。原联合启动脚本会在任一子服务异常退出时关闭另一个服务，放大为整站断连。
- Vite 代理在 API 不可达时可能返回无结构化错误码的 500；真实 API 500 会返回 JSON `code` 和 `message`，可据此区分。
- 仓库源码和构建产物中不存在报错的 `sidebar.js` / `getComputedStyle` 调用，该异常来自浏览器扩展注入脚本，不修改本项目代码。

## 实施结果

- 联合启动脚本会明确打印先退出的服务，并保留仍正常运行的另一项开发服务。
- 管理后台将网络断开和 Vite 代理断连转换为可操作的中文提示。
- 存储文件、应用密码和分类管理页面增加重新连接按钮。
- 新增 API 客户端回归测试，覆盖 Fetch 断连和 Vite 代理 500。
- 清理隔离数据库副本、诊断账号、一次性数据库检查代码及全部调试进程。

## 验证结果

- `pnpm --filter @bookmark-vault/admin-web lint`：通过。
- `pnpm --filter @bookmark-vault/admin-web test`：17 项通过。
- `pnpm --filter @bookmark-vault/admin-web build`：通过。
- `cargo test --manifest-path services/api/Cargo.toml`：19 项通过。
- 联合启动实测：前端 56993 与 API 26626 正常监听，健康检查 200，受保护接口未登录返回 401。
