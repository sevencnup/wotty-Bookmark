# 备份 API 404 诊断记录

## 现象

管理后台通过局域网地址访问时，请求 `/api/v1/backups/settings` 与 `/api/v1/backups/runs` 返回 404，数据备份页显示无法连接。

## 目标

确认请求在管理后台开发服务器、Vite 代理和 Rust API 三个边界中的实际落点，并修复导致备份 API 无法访问的配置或运行时问题。

## 执行步骤

1. 检查 Vite 代理、开发启动脚本和当前监听端口。
2. 分别请求管理后台端口与 API 端口，形成可重复的 HTTP 验证闭环。
3. 根据结果修复单一故障边界，并为代理配置补充回归验证。
4. 执行相关前端和后端测试、构建与格式检查。
5. 更新开发记录和版本记录，完成本地 Git 提交。

## 诊断结果

- `apps/admin-web/vite.config.ts` 已将 `/api` 代理到 `http://127.0.0.1:26626`，局域网访问管理后台不会绕开该规则。
- 直接请求 `127.0.0.1:56993/api/v1/backups/settings` 与 `127.0.0.1:26626/api/v1/backups/settings` 均返回 404；健康检查均返回 200。
- 当前 API 进程和可执行文件的启动/编译时间为 2026-09-11 19:46，早于备份路由加入的提交，因此运行中的是旧二进制。
- 结论：重启 API（或重启 `pnpm dev` 的整套开发服务）让其重新编译并加载当前代码即可；无需修改代理配置或备份数据。
