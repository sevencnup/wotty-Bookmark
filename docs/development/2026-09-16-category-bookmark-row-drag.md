# 分类管理书签整行拖拽归档修复

## 问题

分类管理的书签列表只有六点拖拽手柄设置了原生 `draggable`。用户从书签图标、标题、域名或行内空白处按住拖动时，不会产生拖拽事件，无法拖到右侧资源管理器文件夹。

书签行的连续多选逻辑还会在按下时调用 `preventDefault()`，可能干扰整行原生拖拽的启动；拖拽结束后也没有显式取消连续多选状态。

## 目标与验收

1. 每一条书签行均是拖拽源，按住图标、标题、域名或行内空白处拖动可归档至右侧文件夹。
2. 拖动一条已选书签时，保留现有逻辑并同时移动全部已选书签。
3. 复选框、外链和六点手柄的点击行为不受影响。
4. 拖拽开始不应触发连续多选，结束时必须清除连续多选状态及拖拽高亮。
5. 保留原生 DnD 的 `text/plain` 书签 ID 载荷，确保目标文件夹的既有落点逻辑无须改变。
6. 通过管理后台单元测试、类型检查与生产构建。

## 实施步骤

1. 将书签拖拽回调类型扩大到整行元素，并将 `draggable` 与开始/结束事件绑定到书签行。
2. 移除连续多选启动时对原生拖拽的默认行为拦截，拖拽结束时清理选择绘制状态。
3. 更新使用提示和拖拽可视反馈。
4. 增补拖拽 ID 解析回归测试，运行完整验证。
5. 更新版本记录并创建本地 Git 提交。
