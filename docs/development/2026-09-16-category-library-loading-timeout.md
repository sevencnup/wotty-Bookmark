# 分类管理书签库无限加载保护

## 问题

分类管理页面首次加载时直接等待 `/api/v1/library`。请求层没有超时或中止保护；当浏览器到 Vite 代理或 API 的连接处于挂起状态时，`getLibrary()` 永不结算，页面的 `loading` 状态也永远不会结束。

已确认本机 SQLite 完整性正常，1,289 个活动节点无循环、无孤儿节点，直接查询耗时约 53ms，因此不是文件夹树递归或数据库数据异常导致的卡死。

## 目标与验收

1. 所有走统一 API 请求层的请求必须有明确的响应时限。
2. `/api/v1/library` 挂起超过时限时，分类管理必须退出加载页并显示可重试的中文错误，不再无限转圈。
3. 请求成功、HTTP 错误和既有网络错误处理保持不变。
4. 添加回归测试：模拟一个只会等待中止信号的请求，断言请求在超时后以 `request_timeout` 错误结束。
5. 通过管理后台完整测试、类型检查和生产构建。

## 实施步骤

1. 在管理后台统一 `request` 封装中加入 AbortController 与 15 秒超时。
2. 将超时转换为明确、可重试的 `ApiRequestError`。
3. 添加 API 层回归测试并验证红绿流程。
4. 运行完整验证，更新版本记录并创建本地 Git 提交。
