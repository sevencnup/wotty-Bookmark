# Floccus 快速恢复同步基线

## 背景

旧的服务器 XBEL 缺少 Floccus 节点 ID。即使后台已修复未来的 ID 持久化，Floccus 首次“向上推一次”仍会先下载旧树，并对 1000 多个 `NaN` 节点执行映射、差异计算和强制重试，恢复耗时明显高于正常同步。

## 目标

- 在管理后台提供显式的“快速重建同步文件”操作。
- 操作前保留服务器旧 XBEL 的历史版本，确保可恢复。
- 有活跃 Floccus 锁时拒绝重置，避免破坏正在执行的同步。
- 只清除服务器同步基线和后台索引，不修改浏览器本地书签。
- 重置后 Floccus 读取正式 XBEL 得到 404，可直接由浏览器树创建新文件，跳过旧 `NaN` 树的全量对比。

## 实施步骤

1. 新增登录会话保护的恢复接口。
2. 接口检查 `bookmarks.xbel.lock`：存在有效锁时返回冲突，要求先取消 Floccus 同步。
3. 在数据库事务外先调用已有历史快照逻辑备份正式 XBEL。
4. 删除正式 XBEL 文件，保留 `dav_files` 元数据与 `file_versions` 历史链。
5. 在数据库事务中清空 `bookmark_nodes` 和 `bookmark_sync_state`。
6. 管理后台迁移提示页增加危险操作按钮和二次确认。
7. 重置成功后显示下一步：在 Floccus 执行一次“向上推一次”。
8. 增加后端回归测试，验证活跃锁阻止重置、无锁重置保留历史版本并清空基线。
9. 运行 API、管理后台类型检查、测试和构建，更新记录并创建本地提交。

## 安全操作顺序

1. 用户先取消当前 Floccus 同步，等待扩展停止。
2. 点击“备份并快速重建”。
3. 接口成功后，在 Floccus 执行一次“向上推一次”。
4. 推送完成后恢复推荐的合并策略，并刷新管理后台。

## 完成结果

- 新增登录会话保护的快速重建接口，并在操作期间持有独占 WebDAV 锁。
- 活跃 Floccus 锁会返回 423，旧文件、索引和历史版本均保持不变。
- 无锁时先创建版本快照，再删除当前同步基线并清空书签索引与最高 ID 状态。
- 当前同步状态以正式 XBEL 是否实际存在为准，历史版本元数据不会误报为当前文件。
- 管理后台迁移提示提供二次确认按钮和明确的下一步操作。
- 回归测试覆盖锁冲突、历史快照、WebDAV 404、索引清空和首次重新上传。
